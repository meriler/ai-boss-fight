# Лог решений и выполнения — «Направленный добор»

Заполняется скиллами /код и /ревью по ходу выполнения задач из `.docs/tasks/`.

## Архитектурные решения (зафиксированы при декомпозиции, 2026-07-15)

- **D1. Метка плиток — «таких у ИИ меньше всего», не «ИИ этого не видел».** Базовый урок
  обязательно собирает все 4 квадранта (6/6/3/3) — «не видел» было бы ложью (капкан C1,
  Codex раунд 2). Счёт по квадрантам: статическая база + лог завершённых наборов ×3,
  size у примеров не хранится.
- **D2. Выход из меню без проверки существует только при 0 завершённых наборов.** После
  первого набора модель уже изменена — выход только через обязательную проверку
  (закрывает F3 без «пометки неактуальности»).
- **D3. Тап пишется в лог по ЗАВЕРШЕНИИ набора (3/3).** Недоигранный набор (stuck,
  авто-выход) рекомендацию не сдвигает.
- **D4. Outcome не деградирует.** Ранг partial < fixed; menu-проверка может апгрейдить,
  даунгрейд запрещён. Заголовок финала и сертификат печатают лучший счёт (bestRes2).
- **D5 (исправлено reality-check 15.07). e2e-postlesson.mjs НЕ правится.** Ранняя версия
  плана считала, что он тестирует старую рельсу fMore → startTask('t2a') — это мираж:
  `#fMore` не упоминается ни в одном e2e-файле (grep). Все ~150 существующих ассертов
  остаются без изменений; упавший postlesson = реальный регресс кода, не устаревший тест.
- **D6. Один файл — последовательные волны.** Все задачи меняют v5.html, параллельного
  выполнения нет; e2e-menu.mjs наращивается инкрементально от задачи к задаче.
