## Описание
После обязательной проверки menu-добора финал и сертификат должны печатать ЛУЧШИЙ достигнутый счёт (`MENU.best` против baseline), а НЕ текущий (который мог упасть, если ребёнок докормил «похожим»). Это закрывает капкан C3 (один `res2` перезаписывается и утаскивает 4/4-ребёнка в регресс) и болевые точки F4/F7/adhd#2. Мини-ТЗ v1.1 п.5.

## Технические заметки
- **Решение по baseline (зафиксировано здесь по мандату мини-ТЗ п.5).** `MENU.baseline = GUIDE.res2` захватывается ОДИН раз — в момент, когда `#fMore` открывает меню (код входа добавляет TASK-2). Это единственная точка, где `res2` ещё равен до-menu-значению; после первой menu-проверки `GUIDE.res2` перезаписывается. Поэтому: baseline ставит TASK-2 (вход в меню), TASK-4 (обязательная проверка) обновляет ТОЛЬКО `MENU.best = betterRes(MENU.best||baseline, {correct,total})` и НИКОГДА не переписывает baseline. TASK-5 их только читает. Это надо держать согласованным между TASK-2/4/5 — при ревью проверить, что baseline не переустанавливается в проверке.
- `betterRes(a,b)` (TASK-1) сравнивает по `correct`; при отсутствии menu-добора `MENU.best` может быть `null` → фолбэк на `GUIDE.res2` (обычный путь урока без меню не меняется).
- Заголовок исхода не должен деградировать: если baseline-outcome `fixed`, а текущая проверка дала бы `partial` — заголовок остаётся `fixed` (ранг задаёт TASK-4). TASK-5 читает итоговый `GUIDE.outcome` уже не-деградировавшим.
- Обычный (не-menu) финал НЕ трогать: при `MENU.best===null && MENU.taps` пустой — `showFinal` печатает ровно как раньше (строка :1674), чтобы `e2e-ws.mjs`/`e2e-home.mjs` остались зелёными.
- Тексты — «ёлочки», без нейрооборотов, эмодзи допустимы (это детский UI).
