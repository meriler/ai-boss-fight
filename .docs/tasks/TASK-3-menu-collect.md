## Технические заметки
- **F1 (техкапкан).** `startTask('t2a')` сам зачейнит `t2b→проверку→финал` через `nextAfterTask` (:1136). Menu-режим строит task напрямую и в блоке завершения `tickGuidedTeach` (:1127) уходит в свою ветку — никакого `nextAfterTask`.
- **F2 (техкапкан).** После финала `NAV.lesson=null` (:1656) → guard «не пускать в мутирующие зоны посреди замера» обходится прямым тапом по зоне. Якорь `{kind:'gteach'}` на старте набора возвращает guard (`navGo` :1045 уже блокирует shoot/range/prize при `NAV.lesson.kind==='gteach'`).
- **C6.** Общий stuck (:1121) только советует позвать ведущего и не возвращает в меню. Menu-режиму нужен свой таймер 15 с и явная отмена набора (строгий гейт «большой кулак»/«маленькая ладонь» — дети застревают).
- **C7 (недоопределённость снята).** «Добавление» = 1 плитка = 3 кадра. Session-wide `MENU.taps` кормит `quadCounts()` (весь урок), отдельный `cycleSets` — лимит 2 до проверки (обнуляется после проверки в TASK-4). Это осознанное разделение (флаг решения — см. ниже).
- **Решение исполнителя (зафиксировано здесь):** два счётчика — `MENU.taps` (session, для статистики квадрантов) и `MENU.cycleSets` (per-cycle, для лимита 2 и видимости «К финалу»/«Проверить»). Реплика «разного/похожего» в TASK-5 читает тапы ТЕКУЩЕГО цикла (например срез `MENU.taps` от маркера последней проверки) — согласовать с TASK-5.
- **Кадры незавершённого набора** остаются в KNN (уже добавлены `addExample`). Счёт квадрантов идёт по `MENU.taps`, а не по кадрам — поэтому «недописанный тап» не искажает рекомендацию. size у кадров не хранится (F7) — это ок.
